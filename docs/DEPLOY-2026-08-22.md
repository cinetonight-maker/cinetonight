## Deploy warnings — all benign, all expected on every future deploy

**1. `"no such Durable Object class is exported from the worker"` (DOQueueHandler)**

False alarm. Verified directly in the built worker:

```
export { DOQueueHandler } from "./.build/durable-objects/queue.js"
```

The class *is* exported. Wrangler's startup checker does not follow a
re-export chain, so it warns regardless. Its own text concedes
*"historically this was not a startup-time error."* No action.

**2. `OpenNext is not fully compatible with Windows` / WSL suggestion**

Advisory. The build has produced correct output on this machine across every
deploy so far, and `predeploy-check.mjs` exists precisely to catch the one
Windows-specific failure that did occur (stale build detection).

**3. `The "middleware" file convention is deprecated. Please use "proxy"`**

Next.js 16 rename. `middleware.ts` still works. The codemod
(`npx @next/codemod@canary middleware-to-proxy .`) is a rename, not a
behaviour change — but it touches the single file every request passes
through, including the R2 guard and the admin allowlist. **Not worth doing
in the same window as a release.** Queue it for a quiet moment with a full
test run.
